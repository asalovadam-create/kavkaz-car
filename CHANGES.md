# Обновление 2 (по итогам запуска)

**Тарифы и объявления**
- Тариф закончился → объявления сверх лимита бесплатного тарифа **приостанавливаются** (статус «Тариф закончился»), остаётся самое раннее (на FREE это 1 шт.). Ничего не удаляется. Проверка идёт сама раз в минуту, планировщик не нужен.
- Купили/продлили тариф (оплата, промокод, админ) → приостановленные объявления **возвращаются в каталог автоматически**.
- Тариф владельца больше не виден на карточках, на странице объявления и на странице проката. Виден только владельцу в его профиле и кабинете.
- Покупка тарифа — через поддержку: кнопка «Подключить» создаёт заказ и показывает номер заказа и контакты поддержки. Контакты задаются в админке («Настройки сайта»), переменные окружения не нужны.

**Центр уведомлений**
- Колокольчик в шапке (с числом новых) и страница `/notifications`; ссылка также в профиле.
- Сюда приходят сообщения от администрации и все действия админа по аккаунту: тариф, статус и удаление объявлений, решения по жалобам, подтверждение телефона, сброс пароля, окончание тарифа.
- Админ пишет пользователю из раздела «Пользователи» → «Написать».

**Сессии**: админка и сайт теперь используют **разные cookie** (раньше одну общую). Вход в админку больше не стирает клиентский вход, а действие админа не вызывает «Сессия устарела». Админ выходит после 2 часов без действий (было 30 минут). Просроченная форма теперь возвращает назад с понятным сообщением вместо страницы ошибки.

**Защита админки**
- Адреса `/admin` на сайте нет: он отвечает такой же 404, как любая несуществующая страница. Админка — на секретном адресе (`ADMIN_PATH`), он не упоминается в robots.txt, sitemap и в HTML.
- Двухфакторный вход (приложение-аутентификатор): `flask --app app.py enable-admin-2fa`.
- Необязательное ограничение по IP (`ADMIN_ALLOWED_IPS`), `ADMIN_SECRET`, cookie админки: только на своём адресе, `SameSite=Strict`, `HttpOnly`, `Secure`.
- Страницы ошибок больше не индексируются и не отражают введённый адрес.

**Интерфейс на телефоне**: карточки машин — одна крупная в ряд (фото 16:10, крупные кнопки), у машин без фото аккуратная заглушка, исправлены отступы поиска, подсказки «Для чего нужна машина?», логотип.

**Страница «О проекте»** (`/about`) с данными об основателе и разметкой для поисковиков — заполняется в админке.

# Что сделано в этом обновлении

## 1. Почему кнопки «не работали» — главная находка

В заголовках безопасности стоит `script-src 'self'`: браузер **блокирует любой JavaScript, написанный прямо в HTML**
(`onclick=`, `onchange=`, `<script>…</script>`). А шаблоны были полны именно такого кода. Поэтому были мертвы:

| Что | Почему |
|---|---|
| Переключатель «Я владелец — сдаю свои автомобили» | `onchange="this.form.requestSubmit()"` заблокирован — переключатель ничего не отправлял |
| Быстрые фильтры каталога (С водителем, Свадьба…) | `onclick="toggleParam(...)"` |
| Кнопка «Поделиться» | `onclick` |
| Удаление/замена фото в форме авто | inline `<script>` |
| Подтверждение удаления в админке | `onsubmit="return confirm()"` — удаление шло **без** вопроса |
| Форма «Помогите выбрать» | inline `<script>`; без JS форма слала POST и показывала голый фрагмент HTML без дизайна |

Теперь весь JS в `static/js/app.js` и включается через `data-атрибуты`. Inline-JS в шаблонах не осталось.

**Невидимая кнопка «+ Добавить автомобиль» (ваш скриншот):** правило `.section-heading a { color: серый }` перебивало цвет кнопки.
**Шапка, которая «пропадала» при прокрутке:** `html, body { height: 100% }` ограничивал область липкой шапки одним экраном.
**Сердечки и «весы» на карточках** были позиционированы относительно страницы, а не карточки.

## 2. Тарифы и оплата

- Публичная страница `/pricing`: три тарифа, сроки 1 / 3 / 12 мес. (скидки 0 / 10 / 20 % — меняются в `config.PLAN_TERMS`), FAQ.
- Кнопки «Выбрать / Продлить», оформление заказа, страница заказа. Повторный клик не плодит заказы.
- Режим `manual` работает уже сейчас: заявка → в админке «Заказы на оплату» → «Оплата получена» → тариф включается (повторное нажатие безопасно).
- Подготовлен слой под **Rolly Pay** (`payments.py`): создание платежа, вебхук с проверкой HMAC-подписи, сверка суммы, идемпотентность, блокировка строки от двойной активации.
- При повышении тарифа остаток оплаченных дней пересчитывается и добавляется. Понизить тариф, пока действует более высокий, нельзя.
- Промокод гасится атомарно (раньше два одновременных запроса могли использовать его дважды) и больше не может «понизить» платный тариф.
- Счётчик поднятий считался на весь срок подписки и не обнулялся (на годовом тарифе поднятия кончались навсегда). Теперь — скользящие 30 дней (`BoostLog`).
- Все обещания на странице тарифов теперь реально работают: статистика по каналам, значок PRO, страница проката, приоритет в выдаче.

## 4. Безопасность

| Было | Стало |
|---|---|
| Реальный пароль БД Neon в `.env.example` (и в истории Git) | Заглушки. **Пароль нужно сменить в Neon** — см. ниже |
| Открытый редирект в `?next=` на входе/регистрации | Разрешены только пути своего сайта |
| IP клиента брался из подделываемого `X-Forwarded-For`; без ProxyFix IP — всегда адрес прокси | `ProxyFix`; обход лимитов подстановкой заголовка невозможен |
| Rate-limit считал даже открытие страницы (5 раз обновил `/login` → «слишком много попыток») | Считаются только POST |
| Перебор пароля с разных IP | Лимит неудачных попыток на номер (8 / 15 мин), без утечки «есть такой номер или нет» по времени ответа |
| Пароль любой длины (DoS через scrypt) | Максимум 128 символов |
| Подделка cookie при слабом `SECRET_KEY` = вход под любым пользователем и админом | Сессия привязана к хэшу пароля; смена пароля завершает чужие сессии |
| `ADMIN_SECRET` нигде не использовался | Доп. код при входе в админку (если задан) + лимит неудачных попыток |
| Владелец мог вернуть в каталог **заблокированное модератором** объявление | Статус меняется только между «опубликовано» и «пауза» |
| Лимит автомобилей обходился открытием мастера в двух вкладках | Проверка при самой публикации |
| Удаление авто падало (500), если у него был хоть один просмотр | `purge_car` чистит просмотры, обращения, избранное, жалобы, поднятия |
| Неотмеченный чекбокс «Автомат» всегда оставался «Автомат» | Исправлено |
| Черновик объявления лежал в cookie (лимит ~4 КБ): много фото → браузер выбрасывал cookie → вас «разлогинивало» | Черновик в БД |
| Ссылки WhatsApp/Telegram/tel строились из сырого текста | Телефоны и username проверяются при вводе и при построении ссылки |
| Нет цены/года/мест-валидации на сервере (цена −5) | Проверки диапазонов |
| Проверка фото грузила картинку в память до проверки размера | Размер и формат — до полной декодировки |
| Сессия админа продолжала жить у деактивированного админа | Проверяется на каждый запрос |
| Просмотры считали боты и сам владелец | Фильтруются |

Дополнительно: `object-src 'none'`, `Cross-Origin-Opener-Policy`, разный `Cache-Control` для гостей и вошедших
(кнопка «Назад» в каталоге не теряет место), `noindex` для приватных страниц, `robots.txt` закрывает кабинет/админку/оплату.

## ЧТО НУЖНО СДЕЛАТЬ ВАМ (по порядку)

1. **Сразу: смените пароль БД в Neon** и обновите `DATABASE_URL` на Render. Старый пароль лежал в репозитории
   (`.env.example` и архив `admin.zip` в истории Git) — считайте его утёкшим. Удаление файла из репозитория не стирает историю.
2. На Render проверьте переменные: `SECRET_KEY` (длинный случайный; если там было «change-me…» — замените), `ADMIN_SECRET` (задайте),
   `SUPPORT_TELEGRAM` / `SUPPORT_WHATSAPP` / `SUPPORT_PHONE`, `UPLOAD_PROVIDER=cloudinary` (диск Render стирается при перезапуске — фото пропадут).
3. После деплоя **все пользователи и вы в админке выйдете из аккаунта один раз** (сессии теперь привязаны к паролю) — это нормально.
   Если включили `ADMIN_SECRET`, вход в админку потребует этот код.
4. Если у вас сохранился файл `.env` локально — он не входит в этот архив, ваш остаётся как есть; в него добавьте новые переменные из `.env.example`.

## ЧЕСТНО О ПРОВЕРКЕ

В моей среде нет интернета и нет SQLAlchemy, поэтому **приложение целиком с настоящей базой я не запускал**. Что проверено реально:
синтаксис всех Python-файлов и JS; каждая ссылка `url_for` в шаблонах ведёт на существующий маршрут; все 60+ шаблонов
отрендерены с тестовыми данными (гость / клиент / владелец / админ); 24 теста логики и 12 HTTP-тестов безопасности (CSRF, rate-limit,
подделка `X-Forwarded-For`, HSTS, вебхук) проходят. Что **не** проверено: запросы к БД и сквозные сценарии — для них написан
`tests/test_smoke_db.py`. Прогоните его и откройте сайт на тестовом окружении Render до выкатки на боевой.

Rolly Pay: формат их API мне неизвестен, поэтому `RollyPayProvider` — типовая схема, которую нужно сверить с их документацией.
Юридические тексты (оферта, возвраты) при включении онлайн-оплаты покажите юристу.
